# AmpliGluonMultiplet

`AmpliGluonMultiplet` evaluates tree-level, fixed-helicity, full-colour squared
matrix elements for

```text
g g -> n g,  n >= 2
```

in a normalized SU(3) multiplet basis.  It uses the adjacent-adjoint swap
tables generated by `Wigner6j`; it does not contain a second set of Wigner
coefficients or convention conversions.

The implementation is modern Fortran (Fortran 2018) and follows the useful
execution structure of AmpliCol's `imode=2`: initialization constructs a
process-specific evaluation plan, while each subsequent call only evaluates
one supplied helicity configuration.

## Build and test

From the repository root:

```sh
make -C AmpliGluonMultiplet
make -C AmpliGluonMultiplet test
```

The test target defaults to
`Wigner6j/data/su3_adjoint_swap_prefix_4.tbl` for the complete four- through
eight-gluon suite.  It also repeats the matrix-element checks through five and
seven gluons with prefix-2 and prefix-3 tables, respectively.  Override the
table variables in the Makefile if needed.  A bounds-checked build is available
with:

```sh
make -C AmpliGluonMultiplet debug
```

No library other than a Fortran 2018 compiler is required.

## Benchmark all three implementations

The top-level `Benchmark` harness generates random RamboOnDiet phase-space
points and compares AmpliGluonMultiplet with the fundamental-trace
`AmpliGluonTrace` and the DDM-basis `AmpliGluonAdjoint`. It reports
initialization and evaluation timings as well as every colour-summed squared
matrix element:

```sh
make -C Benchmark
```

See `Benchmark/README.md` for sampling, compiler, and report options.

Random massless phase-space points can be generated reproducibly with the sibling
RamboOnDiet driver:

```sh
make -C RamboOnDiet
RamboOnDiet/build/generate_ampligluon_events 4 5 random/gg_to_4g 1000 12345
```

See `RamboOnDiet/README.md` for its output naming and helicity conventions.

## Library interface

The reusable entry point is `ampligluon_multiplet_t`:

```fortran
use ampligluon_multiplet, only: ampligluon_multiplet_t
use ampligluon_multiplet_kinds, only: dp

type(ampligluon_multiplet_t) :: amplitude
complex(dp), allocatable :: basis(:)
real(dp) :: p(0:3, 5), matrix2
integer :: helicity(5)

call amplitude%initialize(3, 'Wigner6j/data/su3_adjoint_swap_prefix_4.tbl')
call amplitude%evaluate(p, helicity, basis, matrix2, &
                        strong_coupling=1.0_dp, &
                        average_initial_colours=.false., &
                        use_mhv_optimization=.true.)
```

`initialize` takes the number of final-state gluons. Its Wigner-table parsing,
path enumeration, and sparse adjacent swaps are reusable. Generic-helicity
subset partitions, sorting DAGs, currents, and workspaces are initialized
lazily on the first sector that needs them. Call `evaluate` repeatedly on the
same object for new momenta or helicities. An object owns mutable workspaces,
so use one object per thread for concurrent evaluation.

For pure-gluon tree amplitudes, `evaluate` applies the exact helicity selection
rule before constructing currents. After crossing the two incoming gluons to
the all-outgoing convention, configurations with fewer than two helicities of
either sign return an exactly zero multiplet-basis vector and squared matrix
element.

Configurations with exactly two all-outgoing helicities of either sign use an
exact MHV/anti-MHV inverse-soft recursion. Every intermediate coefficient is
kept in the same normalized, diagonal multiplet basis as the public output.
Emission of a gluon is a matrix-free sandwich of existing Wigner swaps and the
normalized antisymmetric `8 x 8 -> 8` vertex; it does not construct a trace or
DDM vector and it leaves the final colour sum as the Euclidean norm of the
multiplet coefficients. One serial colour-ordered Berends--Giele amplitude
fixes the common external-wavefunction phase only. Numerically unsafe spinor
denominators fall back to the general multiplet recursion.

`use_mhv_optimization` is an optional per-evaluation switch and defaults to
`.true.`. Set it to `.false.` to bypass the analytic MHV/anti-MHV path and use
the general diagonal-multiplet Berends--Giele recursion for every nonzero
helicity configuration. The exact all-plus/one-minus selection rule remains
active, so analytically zero configurations still return before BG reduction.

All remaining nonzero helicity sectors, including NMHV, continue to use the
general diagonal-multiplet Berends--Giele recursion. An exact path-basis CSW
construction has been convention-tested, but its naive per-channel sorting is
slower; the shared-DAG design required to make it competitive is recorded in
`DERIVATION.md` rather than silently substituting a DDM backend.

## Table depth

`MAX_PREFIX_GLUONS = p` bounds the minimum number of adjoint fusions used to
reach the outer-representation labels supplied to the local swap table.  It is
not the number of gluons stored to the left of that representation in one
particular basis path.  Closing a `k`-gluon current with its open adjoint gives
a chain of `k+1` adjoints.  A representation at position `j` is reachable from
both ends of the chain, so its minimum fusion depth is at most
`min(j, k+1-j)`.  The sufficient cutoff enforced by the current one-sided path
catalog and swap construction for `N` total gluons is therefore

```text
MAX_PREFIX_GLUONS >= floor(N/2).
```

The current implementation consequently accepts a prefix-`p` table through
`2*p+1` total gluons, or through `g g -> (2*p-1) g`.  This is the consumer's
cutoff, not a claim that a different recoupling construction could not use a
shallower table.  The requirements at the permanently tested multiplicities
are:

| Process | Total gluons | Required prefix | Open-current length | Basis amplitudes |
|---|---:|---:|---:|---:|
| `g g -> 2 g` | 4 | 2 | 3 | 8 |
| `g g -> 3 g` | 5 | 2 | 4 | 32 |
| `g g -> 4 g` | 6 | 3 | 5 | 145 |
| `g g -> 5 g` | 7 | 3 | 6 | 702 |
| `g g -> 6 g` | 8 | 4 | 7 | 3598 |

Thus the default prefix-4 table passes the complete structural and numerical
regressions through eight total gluons and supplies the current consumer's
Wigner cutoff at nine.  The checked-in prefix-6 table supplies that cutoff
through thirteen.  Runtime and memory growth are separate from this
table-depth bound.

## Optimizations

The runtime recursion has been compiled into a flat subset DAG:

- currents are evaluated in increasing subset size, without recursive calls;
- one representative of every unordered bipartition is used;
- the antisymmetry of the colour bracket and kinematic vertices removes the
  reversed duplicate;
- all partitions of a subset feed one shared adjacent-swap sorting DAG, so
  common partial recouplings are evaluated once;
- path-reflection phases are obtained from local vertex parities and an
  explicit conjugate-reversal lookup in `O(P*N)` time and `O(P)` memory;
- sorting-DAG coefficients retain only two adjacent inversion layers, reducing
  their storage from all graph nodes to twice the maximum layer width;
- complete paths are interned through open-addressed hash tables during plan
  construction, avoiding quadratic path searches for deeper tables;
- Wigner swaps are stored and applied sparsely;
- MHV and anti-MHV sectors use sparse, matrix-free radiation directly between
  successive diagonal multiplet bases;
- generic ordering plans and Berends--Giele workspaces are allocated lazily,
  so an MHV-only object does not retain their high-multiplicity memory;
- exact all-plus and one-minus sectors (and their parity conjugates) return
  before any colour or kinematic recursion;
- the four-gluon interaction is split through a nonpropagating antisymmetric
  tensor, leaving only binary merges;
- the tensor current which cannot reach the final closure is removed by a
  backwards dead-tree check; and
- all allocated current and recoupling workspaces are retained for reuse.

The independent convention derivation is recorded in
[`DERIVATION.md`](DERIVATION.md).
The evaluated canonical-plus-reverse ordering alternatives, including their
`N=8-10` operation counts and single-core measurements, are recorded in
[`ORDERING_OPTIMIZATION.md`](ORDERING_OPTIMIZATION.md).

## Validation and scope

The permanent regressions check path counts, reflection signs, merge seeds,
and sorting-layer metadata through nine total gluons; dense sparse-swap
properties through eight; and fixed matrix elements through eight.
Fixed-helicity colour sums were compared independently with the original
AmpliCol `imode=2` implementation through `g g -> 6 g`. The timing harness
checks AmpliGluonMultiplet against AmpliGluonTrace and AmpliGluonAdjoint on
every run. Nonzero values agree at floating-point roundoff, while analytically
vanishing sectors remain at numerical noise.

Current scope is pure-gluon, tree-level SU(3).  Phase-space generation,
quarks, loop amplitudes, and helicity summation are intentionally outside this
module.
